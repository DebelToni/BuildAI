User Acceptance Testing (UAT) Examples

This page lists high‑level scenarios a stakeholder can walk through to confirm that BuildAI behaves as expected. Each scenario is phrased in Given/When/Then form and maps back to one or more User Stories.

#ScenarioAcceptance Criteria
UAT‑01Generate text with a trained checkpoint
Given a SUPER‑GIANT checkpoint on disk
When I run generate.py with a prompt
Then I receive a non‑empty completion within 3 seconds
  • Exit code 0
  • Stdout contains at least one token beyond the prompt
  • Total latency ≤ 3 s on an A100‑40G
UAT‑02End‑to‑end chat with LADA using local models
Given Ollama is running llama3
When I open /chat and ask “Explain quicksort in Python”
Then I receive a code answer in under 10 seconds
  • Router selects coder backend = ollama:llama3
  • Response includes a fenced Python block
  • Token stream starts ≤ 5 s after send
UAT‑03Orchestrator planning flow
Given orchestration is turned ON
When I ask “Build a Flask CRUD app”
Then router forwards to orchestrator; orchestrator spawns ≥1 coder; final answer aggregates code files
  • Server logs show orchestrator → spawn coder
  • UI shows progressive planning steps
  • Final zip bundle is offered for download
UAT‑04Cloud deployment on RunPod
Given I run ./deploy-runpod.sh with valid API key
When Terraform finishes
Then the public endpoint returns 200 for /health
  • Terraform exit code 0
  • Remote /health returns JSON {"status":"ok"}
  • CUDA visible devices ≥ 1
